# 注册、客户分级与售后房：使用与验收状态

更新：2026-10-22。下述普通会员规则覆盖历史“注册默认一级”。

## 从个人账号到客户管理

在/account注册，完成本人手机号、图片/短信验证码及密码设置，注册为普通会员。不自动关联customer、room、设备或管理资格；普通账号页面只显示本人资料。验证码和新密码由本人在可信页面完成，不进入聊天、URL、脚本、日志或Git。注册/重置未知结果先核原事务。

管理入口/manage独立。只有保留内置admin可授予或撤销管理员；客户管理员的1–10级仅对明确serverId/customerId/userId有效，不跨客户、不成为超级管理员。设备在客户端登录账号后另做原安装签名及原生身份验证，浏览器登录不是设备绑定。

|关系|默认/依据|
|---|---|
|个人账号|普通会员，无管理资格|
|客户管理员|admin在选定客户显式授予1–10级|
|房间成员/管理员|原ID及签名审批；管理员资格仅admin可授予|
|设备等级|未提级设备默认0；邀请不提级，绑定安装身份|

## admin怎样授予客户管理员

选择正确客户，再按用户ID核人。GET /api/v1/manage/customers/{customerId}/managers/{userId}/level取得当前授权。PUT同一路径，JSON {"administratorLevel":2,"expectedRevision":0}；0只是首次授权示例，必须用读回revision。null表示撤销而非0级管理员。成功后读回客户、role、level和revision，让用户从/manage重新登录/刷新。

GET /api/v1/manage/users?customerId={id}&limit=50按nextCursor分页，显示选定客户授权；旧administratorLevel数字不是该客户授权。旧全局PUT /manage/users/{id}/level属于兼容数据，不用于新客户授权。历史自动一级不恢复成管理员；有待核提示时由admin明确决定。

## 设备等级

GET/PUT /api/v1/manage/devices/{deviceId}/level，写入deviceLevel整数1–10及expectedRevision。仅在已有目标客户管理权、原安装公钥绑定、未撤销时允许。普通客户管理员只能将低级设备提升到自己在该客户的等级，超级管理员可选择更高等级；现有接口不降级。并发409读回，不改目标等级规避审批。邀请/入房不会自动改变经验证的既有等级。

## 仿真时怎样用

售后房仅有效客户管理员可按真实账号/安装与原生身份、当前连接代次和目标许可获得票据；设备owner、房间管理员ID、昵称和旧数字都不是该权限。普通协作房按其已批准成员、等级、目标同意和签名委派协议；更高级目标仍走原同意审批。十级全部跨端真实调用及旧等级路径兼容验收尚未完成，不能据徽标宣布放行。

账号/角色降级、退出、撤销、账号切换或原生重连要复核旧票据失效；普通设备资源可在获授权工具范围内使用，不要求目标模型可用。权限不扩大系统权限、证书使用、硬件PIN或任务租约。

## 排障及交付边界

普通注册用户看不到客户列表是正常隔离；需要管理时找admin授予指定客户。管理会话与个人会话不可混用。INSTALLATION_BINDING_REQUIRED恢复正常持钥注册，不复制别人私钥。等级冲突读取当前revision，未知结果不重放。

2026-10-18默认一级及2026-10-20数字矩阵属于历史证据，不证明2026-10-22普通会员/客户授权及所有真实设备通过。当前服务已部署账号隔离、客户等级及售后策略；签名客户端覆盖、同账号完整协同、跨等级真机、全舰队和新装自动入房仍分别验收。公开说明见[权限验收](https://github.com/caucy2026/skills-group/blob/main/docs/admin-level-acceptance.md)。
