# 异常处理与断联恢复

## 原则：先核原事务

工具超时、仿真失联、SSH拒绝、房间心跳过期与物理离线不同。先查本机控制App/桥，再查原任务、PID/创建时间、日志、回执与真实外部结果。不要凭一次失败重装、重签或重复删除。

## 按症状分流

| 现象 | 处理与验证 |
|---|---|
| 回环桥缺失/连接拒绝 | 核当前控制App实际路径/PID/版本；文件存在不证明桥活着。原控制任务未知时不重启共享App。 |
| consent_pending | 保留原申请，等待目标当次确认；不反复申请或代点首次同意。 |
| remote_disabled | 核原开关与当前意图，在原授权范围恢复；工具/主人明确拒绝不换通道绕过。 |
| identity_mismatch/指纹改变 | 停止目标修改，以独立可信记录核身份；不自动接受新指纹、换号或清数据。 |
| offline/transport_failed | 查控制端、网络和目标进程，使用已登记同机远程桌面/可信备用入口恢复；用户确认关机的设备不盲连或唤醒。 |
| 桌面黑屏/输入无响应 | 核同机ID、焦点、浏览模式、权限、客户端日志与已授权文件通道；不能等同整机离线，不盲点或重装。 |
| 更新后SSH引导HTTP500 | 查原升级状态与目标本机SSH/MCP就绪；初始加载和持续故障分开，先沿桌面对账，不重启安装器。 |
| PAD adbReady=false/offline | 查组件/当前仿真状态；重新connect取得新串口，不继续旧端口、不全局kill-server。 |
| 房间绿点但调用失败 | 核原生身份、连接代次、当前票据、成员/角色/撤销和工具范围；心跳不是调用证明。 |

## Mac文件访问

原SSH已通但获授权文件不能读时：系统设置 → 通用 → 共享 → 远程登录旁ⓘ → 允许远程用户对磁盘进行完全访问。设备持有人在系统正常认证后，从原会话实际读回目标文件。该开关不替代App本身、屏幕录制或辅助功能权限，禁止重置钥匙串/TCC或chmod整个用户目录。

## 模型未就绪

先查原验证请求是否仍在途、是否存在明确失败、描述来源与健康时间。Key文件存在不等于模型可用，健康证明过期也不等于Key失效。部分旧版描述缓存会抑制过期后显式复验；源码已有修复不代表当前商城包已包含。对照当前版本、原请求和发布记录，不连续计费重试、不换用户模型或复制Key凑ready。

认证/额度/输出预算失败保留真实状态；不同错误不能一概让用户充值。未知结果不重发原prompt。无模型仍可执行获授权确定性资源任务，但不能伪造model-ready或签名任务资格。

## 恢复结束

核原ID/指纹、实际进程/版本、真实工具、原配置/授权/会话与房间新心跳。后台在线、打开窗口或重启成功只证明各自范围。局部阻塞继续其他授权工作；确需本人密码/PIN/平台确认时只请求该必要动作。
