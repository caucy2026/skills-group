# 注册、安装与首次接入

## 先注册个人账号

打开[个人账号](https://kemi-chat.newlinksz.com:21122/account)，通过本人手机号、图片与短信验证码注册并设置密码。验证码与新密码由本人在可信页面完成，不进入聊天、脚本、URL或日志。

注册后是普通会员，不自动获得customer、房间、设备绑定或管理资格。浏览器注册和客户端原身份登录分别完成；同账号个人协同不要求先加入集群房间，最终能力以实际客户端和验收结果为准。

## Phone 同账号协同：试用接入与当前限制

**2026-10-25：后端基础接口已部署，手机版完整历史、消息实收、附件和断线恢复仍在真机验收。** 本网站现有 Android 卡片是 PAD 正式包，不是 Phone 下载入口；Mac/Windows 的商城版本也不能据此认定已经支持新版手机协同。以下流程供获批研发/验收包使用，不把组件回归、公证或设备目录可见当作正式手机版已经交付。

Phone 是同账号电脑的操作界面，设备类型为 `phone`：不需要仿真 ID，不开启集群，不入房，不填写 customerId，不在手机配置目标电脑的模型 Key。它不能作为远程仿真或模型/工具执行宿主；模型、文件和会话操作由选中的电脑/PAD原工作台执行。Android 系统本身不能决定它是 PAD 还是 Phone，应核实际客户端形态。

1. 手机与目标电脑配置同一个可信服务地址，例如 `https://kemi-chat.newlinksz.com:21122`，不带 `/vibekits/`。一个客户端连接一个服务Origin；不同服务器的同名账号不自动合并。
2. 在两台设备各自的账号入口登录同一普通账号，完成适用的账号与设备验证。APP自行保护安装密钥；不要让同事发送密码、短信码、token或私钥，也不要把后台管理登录当作个人设备登录。设备以最后成功激活的账号绑定为准，失败登录不能提前清掉原账号。
3. 目标电脑需要支持个人协同宿主的合格版本，并实际保持协同开启、当前账号绑定和新鲜目录心跳。旧仿真在线、房间心跳在线、配置中有模型Key或声明canHost都不能单独证明手机可操作。没有兼容宿主时保留本机工作台，按原同身份升级流程处理，不卸载清数据。
4. 在“我的会话”下的“我的设备”选择在线目标；一台可用目标一个切换项。核昵称、设备类型和当前目标后恢复它原工作区与会话，点击设备不应自动新建会话。明确点击“新会话”才在目标创建，切换时保留各目标自己的草稿，不能把待发内容转送另一台设备。
5. 先只读打开一个已知会话，核对应会话、完整分页历史及后续事件，再发一条唯一测试消息。操作必须区分本地草稿、发送中、服务端接收、目标持久接收、处理中和完成；结果未知先查询原operationId，不连续点击或直接SDK重发。没有其他在线设备与暂时获取失败要分别显示，不能将请求失败写成0台。
6. 附件只有在目标收到实际字节且完整SHA核验通过后才能供目标使用；手机本地路径不能直接当作电脑文件路径。沿目标原有文件、目录和工具授权处理拒绝，不改走仿真或其他入口绕过。文件链路尚未真机通过时明确不可用，不把设备在线当文件共享已完成。
7. 手机退到后台或断网时保留原目标、草稿和游标；恢复后先核当前账号与绑定再补齐。退出账号或换号后，旧凭据、旧事件和旧操作不得继续访问；手机关闭页面不应停止电脑原有任务。这些都是跨端验收要求，仍须在同一最终包逐项证明。

若会话列表能读取而正文中断，应分别核原operation、结果分片清单及接收确认。`completed`不等于手机已显示；`sealed`只说明宿主封装完成，`acknowledged`是源端确认，仍需核GUI。正常快照completion封套不一定带sessionId，缺失字段不能直接推成错会话。保留原草稿和回执，诊断只记错误码、时间、版本、大小与摘要，不复制聊天正文或秘密。

研发同事继续读取[前后端统一协议与M01–M20验收](https://github.com/caucy2026/vibekits/blob/main/docs/development/MOBILE_HARNESS_SAME_ACCOUNT_HANDOFF_20261023.md)、[首次接入及Host Bootstrap后续合同](https://github.com/caucy2026/vibekits/blob/main/docs/development/MOBILE_ACCOUNT_DISCOVERY_SERVER_REPLY_20261024.md)和[可信恢复实测边界](https://github.com/caucy2026/vibekits/blob/main/docs/acceptance/PHONE_TRUSTED_RECOVERY_ACCEPTANCE_20261025.md)。这些文档含历史阶段，按文内后续状态、当前服务capabilities和最终包证据判断，不照搬旧“生产未开放”或“全部已通”的描述。

## kemi业务与newlink通用服务

以下customer与房间步骤用于支持集群的电脑/PAD。Phone按上方个人协同路线接入，不走房间申请审批。

本团队业务客户ID为 **kemi**，协作接入房为 **kemi 通用测试房**（`c0985cc4dfeedaf71515ae029fc4cc4f`）。已有approved成员直接核实时心跳和工具；未加入时按下方原安装身份申请、审批、激活流程操作。其他组织使用其管理员明确分配的customerId。

**newlink**保留独立通用服务关系。当前第一槽是 **通用服务1**（原ID `f450c684b868292f67c534b793e26314`）；它不是kemi业务客户，也不是所有设备必须硬编码加入的房间。客户端只展示自己已分配/加入的服务房，不列出其他服务槽。普通设备只见有效设备管理员，彼此不可见、不可互相仿真；有效设备管理员按当前等级及目标许可维护设备。业务普通协作房继续按有效成员和room-members规则协作。

规划为最多8个服务槽、每槽10000台，服务器按原身份找回既有关系或分配下一有容量的槽，用户退出服务后保留退出决定。**2026-10-25实测生产automaticServiceAssignmentEnabled=false**：自动新装入服务、重装找回及万台真实在线仍不能报完成；不为演示而开启全局功能或把所有设备强塞第一槽。当前设备可在一个服务Origin下加入多个获授权房间，不宣传同时连接多个服务域名。

## 账号管理员与房间设备管理员

只有内置 **admin超级管理员**可任命注册账号为1–10级客户管理员或通用管理员。客户管理员选择customerId，只管理获授客户的全部房间；通用管理员管理本服务器所有客户，不等于超级管理员，也不能任命其他账号管理员。普通注册不再默认一级。

房间中的管理员是**设备管理员**。有权的客户/通用管理员可为已批准设备设置不超过自己等级的设备管理员，0表示撤销显式授权；有效更高权限不能被越权覆盖。账号当前登录的设备可在已加入的相应房间继承账号管理等级，必须核当前绑定、客户会话、原安装/Native身份和授权修订。后台管理员账号与设备管理员是不同对象，设备保护等级也不因普通入房而自动提升。

设备管理员访问同级/低级目标仍核原身份、成员、目标许可、工具范围和有效签名票据；更高目标按原同意审批处理。服务房成员资格不授予普通成员互访。房间身份不代替业务任务唯一租约、本机grant、系统权限或签名材料授权。

## 在线、登录到期与独立授权

集群心跳在线、个人协同在线、模型证明和工具可用分别核验。手机在线电脑0时，检查同账号Host当前绑定、目录心跳和协同凭据期限，不用原MFA尚有效或canHost声明替代在线证明；先对账原恢复事务，不改期限、反复登录或清数据掩盖问题。

客户登录到期后，旧继承管理员快照重验失效；另有有效显式2级设备授权时，只能以独立2级重新解析，不能沿用过期账号4级，撤销该显式来源后也失效。个人协同短凭据到期与房间独立设备授权分别处理。相关[31项合同与负控证据](https://github.com/caucy2026/vibekits/blob/main/docs/acceptance/ADMIN_INHERITANCE_SESSION_EXPIRY_CONTRACT_20261025.md)不代表最终GUI、全舰队或真实未消费票据撤销矩阵通过。

## 先拿到正确的正式包

从网站的平台卡片进入 KEMI 商城。页面显示商城实际版本、整数版本码、大小和 SHA-256；“上次核验”或“同步失败”不等于最新。Mac、Windows、Linux 的产品包名是 com.caucy.vibekits；Android PAD 是 com.vibekits.vibekits。PAD 指 KEMI Android PAD，不是 Apple iPad。

- 核平台、CPU 架构、最低系统、包名、精确字节、哈希和发布签名；没有正式 Linux 包时不使用其他平台文件代替。
- 新版能力以实际商城包与工具目录为准。文档包含后续集群功能，不能据此认定商城旧包已经支持。
- 已有用户采用同身份覆盖安装，保留原路径、配置、登录、Key、会话和设备身份；不要先卸载或清数据。

每个平台卡片都有“扫码下载”。二维码指向对应平台的固定商城分享页，商城更新后仍打开最新正式记录；用相机或扫一扫打开，不把手机版与桌面包混用。

## 各端安装

Linux已于2026-10-16核实正式上架：1.9.0-dev.684（版本码2684），Ubuntu20.04 x86_64/amd64的DEB。下载时仍以商城实时记录为准；这份包不适用于ARM64。先核`dpkg --print-architecture`为`amd64`，按包说明安装并核原设备ID、配置和Key保持。

- Mac：完整解压签名公证 ZIP，按商城说明安装。不能把 App 内的新旧文件合并复制。打开实际安装路径，核“关于”的版本。屏幕录制、辅助功能、文件访问分别按实际需要授权。
- Windows：运行正式签名安装器，核发布者和原安装目录。普通已授权 UAC 确认可按任务处理；未知发布者、新权限、密码或令牌 PIN 不自行绕过。完整安装后核实际 EXE 路径与版本，不单换 EXE 或 DLL。
- Linux：只使用当时公开且匹配 amd64/arm64、发行版要求的正式包；执行项目包内说明，不把 AppImage、deb、源码当成同一种格式。
- PAD：在目标设备下载匹配型号和签名的 APK，由设备主人完成系统安装确认。设备已有宿主时保留数据覆盖；远程安装路线见 PAD ADB 文档。

## 从本机工作台开始

打开 Harness，选自己的工作区。模型账号使用本人的获授权配置，不向同事索取 Key。先验证一个只读工具。模型、工具、仿真和房间在线是四种状态；没有模型的设备也能提供获授权的确定性构建或设备资源。

## 首次仿真验收

目标开启远程仿真，提供原 6–16 位仿真 ID。首次访问由目标主人确认；当前产品开启操作不额外索取仿真密码。操作系统认证仍按实际要求完成。Harness 内直接调用注册 MCP；外部 Mac 使用完整 remote-simulator 技能包。核原身份、真实只读调用，再确认房间心跳。

- 仿真 ID 与远程办公桌面 ID 不混用。
- pending、拒绝、撤销或指纹变化时不执行写操作。
- 每项未验收明确标待验；下载、安装或绿灯都不代替功能验证。
