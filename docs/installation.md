# 注册、安装与首次接入

## 先注册自己的管理账号

1. 打开[管理后台](https://kemi-chat.newlinksz.com:21122/)，选择“验证码注册”；已有账号直接登录。
2. 填写本人中国大陆11位手机号，完成图片验证码，获取并填写短信验证码，进入设置密码步骤；输入两遍不少于8字符的密码后提交。验证码和新密码由本人在可信页面完成，不发给同事或写进聊天、脚本、网址。
3. 注册成功后正常登录，确认“我的账号”显示**一级管理员**。旧版普通管理账号默认也为一级；只有原默认 `admin` 是超级管理员，十级管理员不是超级管理员。
4. 请团队管理员分配你有权使用的客户和房间。**注册成功和账号等级不自动授予已有团队的客户管理权**。看不到 `newlink` 或房间时，先核权限分配，不另建同名房间。

后台账号与客户端设备是两种身份。当前可用接入是“安装客户端 → 原设备身份申请 → 审批激活 → 房间仿真”；不要把浏览器登录当成客户端已绑定此账号。客户端多设备账号登录、同账号自动互通仍在研发，不能按已发布功能使用。

## 先拿到正确的正式包

从网站的平台卡片进入 KEMI 商城。页面显示商城实际版本、整数版本码、大小和 SHA-256；“上次核验”或“同步失败”不等于最新。Mac、Windows、Linux 的产品包名是 com.caucy.vibekits；Android PAD 是 com.vibekits.vibekits。PAD 指 KEMI Android PAD，不是 Apple iPad。

- 核平台、CPU 架构、最低系统、包名、精确字节、哈希和发布签名；没有正式 Linux 包时不使用其他平台文件代替。
- 新版能力以实际商城包与工具目录为准。文档包含后续集群功能，不能据此认定商城旧包已经支持。
- 已有用户采用同身份覆盖安装，保留原路径、配置、登录、Key、会话和设备身份；不要先卸载或清数据。

每个平台卡片都有“扫码下载”。二维码指向对应平台的固定商城分享页，商城更新后仍打开最新正式记录；用相机或扫一扫打开，不把手机版与桌面包混用。

## 各端安装

Linux已于2026-10-16核实正式上架：1.9.0-dev.684（版本码2684），Ubuntu20.04 x86_64/amd64的DEB。下载时仍以商城实时记录为准；这份包不适用于ARM64。先核`dpkg --print-architecture`为`amd64`，按包说明安装并核原设备ID、配置和Key保持。

- Mac：完整解压签名公证 ZIP，按商城说明安装。不能把 App 内的新旧文件合并复制。打开实际安装路径，核“关于”的版本。屏幕录制、辅助功能、文件访问分别按实际需要授权。
- Windows：运行正式签名安装器，核发布者和原安装目录。普通已授权 UAC 确认可按任务处理；未知发布者、新权限、密码或令牌 PIN 不自行绕过。完整安装后核实际 EXE 路径与版本，不单换 EXE 或 DLL。
- Linux：只使用当时公开且匹配 amd64/arm64、发行版要求的正式包；执行项目包内说明，不把 AppImage、deb、源码当成同一种格式。
- PAD：在目标设备下载匹配型号和签名的 APK，由设备主人完成系统安装确认。设备已有宿主时保留数据覆盖；远程安装路线见 PAD ADB 文档。

## 从本机工作台开始

打开 Harness，选自己的工作区。模型账号使用本人的获授权配置，不向同事索取 Key。先验证一个只读工具。模型、工具、仿真和房间在线是四种状态；没有模型的设备也能提供获授权的确定性构建或设备资源。

## 把网址交给智能体自动入房

本团队默认后台账号 `admin`、客户 `newlink`、目标房间和接口发现入口已写进 [入房执行清单](rooms.md) 与 [agent.json](../agent.json)。同事优先注册个人账号并获得团队客户/房间权限；也可在明确授权的代办会话中，经受保护入口提供管理凭据，授权操作自己的本机；智能体自行读取本机原 ID、申请、登录后台核对并审批、激活和验通。首次设备或系统认证仍按实际系统窗口完成，密码不进入公开网页、聊天或脚本。

## 首次仿真验收

目标开启远程仿真，提供原 6–16 位仿真 ID。首次访问由目标主人确认；当前产品开启操作不额外索取仿真密码。操作系统认证仍按实际要求完成。Harness 内直接调用注册 MCP；外部 Mac 使用完整 remote-simulator 技能包。核原身份、真实只读调用，再确认房间心跳。

- 仿真 ID 与远程办公桌面 ID 不混用。
- pending、拒绝、撤销或指纹变化时不执行写操作。
- 每项未验收明确标待验；下载、安装或绿灯都不代替功能验证。
