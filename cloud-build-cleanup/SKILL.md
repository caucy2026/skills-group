# 云端构建用后清理

## 团队必须执行的规则

每个执行者对自己产生的云端构建存储负责。构建结束后必须完成清理并回读验证，不能把旧缓存和重复安装包无限留在账号里。编译、交付和清理是同一项任务的三个阶段；未清理或未报告确切保留原因，不得宣称收尾完成。

云端服务部署也适用：即使服务以Python源码或静态网页运行、没有CI编译，也须在部署与健康核验后清理本任务闲置的临时编译、测试、解包和传输缓存，再回读确认。不能因“源码服务无需编译”跳过已产生的临时缓存。服务目录、虚拟环境/工具链、持久数据、配置、签名材料、最新完整交付和必要回退保持可用；混合目录只删已核实的可再生文件，不整删带源码或备份的staging。

## 构建前确定归属

- 记录提供商、账号/仓库、任务、run ID/attempt、源码SHA、平台和缓存键/产物ID。
- 自有临时缓存优先用任务、源码和attempt唯一标识，避免和其他同事共用可变目录或缓存键。
- 复用仍有效的共享依赖时记录共享归属。共享缓存不是本任务独占缓存，不得为完成清理指标将其删除。
- 确定最新正式产物及必要证据的保留位置，上传产物设置与交付窗口相称的短保留期；禁止无期限保留每次测试包。

## 构建后执行

1. 等本任务和其下载、打包、签名及部署步骤终止。失败的构建先保存最小诊断证据；可恢复的在途构建不清掉恢复输入。
2. 正式包先完成大小/SHA-256和可获取验证，记录源码SHA、run/attempt；确认最新平台包保留完整。未交付完毕的候选不可当废物删除。
3. 删除已确认自有且不再使用的临时编译目录、中间对象、下载/解包副本、临时传输文件和本任务独占CI依赖缓存。构建缓存可重新生成，不为省一次重编而长期积存。
4. 清理旧CI二进制时核对精确ID、名称、源码和平台，保留每个平台最新完整包；当前发布、回滚合同、其他任务引用的产物及源码/文档/密钥不进入删除集合。历史二进制与依赖缓存是不同对象，按实际授权分别处理，不用“缓存”一词掩盖不可逆删除。
5. 使用已有适用授权，直接发起所需工具审批；工具拒绝时说明精确范围和理由，不换工具绕过。正常的任务自有临时缓存收尾不再重复询问一般许可。
6. 回读缓存/产物清单，证明目标ID已消失、保留ID仍存在。记录清理前后字节数、删除集合及保留理由。API成功回执本身不代表账号额度已恢复。

## GitHub Actions具体边界

- 先查运行中、排队和等待任务。没有运行中的任务只能排除并发占用，不能证明账单或预算正常。
- Actions缓存和构建artifacts分别盘点；不把Release正式资产、源码桥接、报告混成缓存。
- 用官方API删除精确cache/artifact ID；不使用仓库或账号的无差别全量删除。
- 历史存储按时间累计。删除后只能降低当前/未来占用，不能清零已累计的使用；不承诺删除后立刻解锁。以新任务的实际执行步骤和正式注释验证是否恢复。
- 预算错误查当前预算、累计分钟、存储及付款状态的证据。没有证据时标记未知，不默认要求提高预算，不改变付费上限或关闭消费限制。

## 交付记录

简洁报告：实际交付包及哈希；清掉哪些任务自有缓存/产物及字节数；保留哪些最新包/源码/证据；是否影响下次冷编译耗时；仍被工具或平台阻断的具体项。不得把其他同事的清理或并发存储变化计作自己的回收成果。

## VibeKits/hbbv 云端容量与本地备份规则（2026-10-21）

本项目用户明确禁止后续在云端创建或保留数据库备份：数据库一致性备份只存本地受控磁盘，权限600、目录700，不入Git。不得先在云端生成完整备份再下载；使用已验证的在线一致性导出至本地方案，或经协调的静止数据库读取方案，不能直接复制正在变化的SQLite主文件冒充一致备份。若本地备份链路尚未具备，先实现并验证，不执行需要备份保障的生产迁移。旧准备脚本含云端backup/数据库复制时不可直接重跑，须先按本规则调整。正式运行数据库、WAL及身份配置不是备份，禁止删除来满足容量指标。

Rust Linux服务优先按`rust-linux-cross-build`在本地冻结源码、测试、交叉编译并核验ELF/GLIBC/哈希，再上传最小交付；hbbv是Python服务，在本地测试后上传必要源码和锁定依赖，无需Rust编译。不在生产云端建立长期编译缓存。用户提出1GB目标时区分临时构建空间与包含正式数据库的服务总空间；现有正式库已超过1GB，不虚报总空间达标，不为目标擅自删业务数据。
