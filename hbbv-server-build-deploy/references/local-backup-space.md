# 备份前本地空间不足

不要先删仍有效的数据库备份、源码、SDK、正式包或在途产物。按本机规则记录数据库重建/临时流和并行任务所需余量，只清已核验的闲置生成物。新备份成功验证后才淘汰旧备份，保留最近3份规则不变。

Mac历史构建先复用目录索引，再逐文件更新身份/生成证据与保留集合；核对实际构建和未来步骤引用，对精确文件分批lsof。旧AOT需确认Dart VM/isolate快照符号，先失效关联stamp；不删除原生资产或冻结包配置。

Xcode的PCM不一定裸CPCH文件头。对象格式可通过 `xcrun clang -module-file-info <精确路径>`识别，模块map和SDK输入必须仍在。若采用解析器，只接受有界且完整的Mach-O MH_OBJECT命令表、有效__CLANG.__clangast节和内部CPCH，拒绝截断、重叠或未知格式；不能仅以.pcm扩展名或Mach-O头证明可删。已安装kemi-storage-cleanup时可复用其只读inspect_clang_module.py，格式识别仍不授予删除权。

开工阈值按当前源库和既定接收器保护计算，不把上轮阶段7GB当永久充分值。项目模板现用3GB恢复保留量 + sourceBytes×1.25，再加1GiB开工余量；其他机器须匹配本机规则和实际配置，不能为达标降低保护。2026-10-21源库约2.520GB时需要超过7.224GB，后续在同范围补清旧生成模块到8.007GB才开工。达到本次阈值即停止新增删除；逻辑大小不等于独占回收，不能宣称全局300GB达标。

完整项目证据：docs/acceptance/LOCAL_BACKUP_SPACE_RECOVERY_20261021.md/json及CACHE_RETENTION_PREDEPLOY_BACKUP_20261021.md/json。具体路径和容量是本次环境实测，其他同事重定本机阈值，不照搬磁盘或旧删除清单。该成果不代表已完成新生产备份、后台部署或整体验收。
