# hbbv协议缓存治理与生产收尾

本项目缓存治理实证见`docs/acceptance/CACHE_RETENTION_PRODUCTION_20261022.md/json`，源回归分别为`test_room_event_retention.py`、`test_device_receipt_retention.py`和`test_room_event_backlog.py`。以下是已验证边界，不授权清理其他数据。

## 两种可清缓存与不可混淆的业务记录

- `room_events`只使房间快照失效；原协议积压超过100条即要求`snapshot_required`。保留最近101条，持久清理水位和删除同一SAVEPOINT，旧游标/重启后恢复快照。每次写入最多清128条，冷房间历史不会因没有新事件而自动收敛。
- `receipts`仅清已认证设备的失效代次。`report`先检查`sessionEpoch`、再查缓存，因此旧代次无缓存也已被拒绝；当前代次所有回执不设新TTL，重试和冲突检测不变。未知/撤销设备保留。用主键两个代次范围、每份新报送最多128条，不扫描或读取响应正文。
- 不清`business_receipts`、`business_events`、`business_messages`、`task_operations`、评分、身份或授权。原未知操作必须保持未知，不为清理或完成率重放、伪造无效果证据。
- SQLite空页可复用不等于文件缩小或磁盘回收。3GB目标不授权在线删库/WAL或无证据VACUUM；必要数据超限如实报告。当前代次长期不换代仍可能增长，不承诺无限期有界。

## 部署中的非显然依赖

先做只落本地的一致性备份，保持三份有效保留及唯一当前标记；再核精确线上文件、旧任务/评分/操作摘要、有效租约和部署锁。一次正常systemd切换，观察超时只对账原事务。

只改工作目录时也应保持原启动参数。当前公钥引用可能仍指向旧release；这属于有效配置和回退依赖，不能因日期旧而清掉。清理暂存文件不触碰当前运行源、原DB/WAL、venv、公钥/私钥及必要旧release。

长内联摘要触发SSH命令长度限制时，按原预算拆成有界的文件集合；本例每命令20项。长程序用既有SFTP上传、验SHA后按精确路径执行，不放宽命令预算或改通道绕过拒绝。

## 测试预算应匹配实际夹具

Linux的虚拟内存与RSS不同。百竞标者用例实际最多16线程；512MiB地址空间和4MiB文件上限曾造成线程创建及SQLite I/O首错。源与断言未变，仅给隔离测试进程设malloc arena=2、虚拟内存1.5GiB、单文件32MiB、CPU120秒/等待300秒，两项首错及全112项通过。该配置是本次夹具的依据，不是生产服务或其他机器的统一最低值。

只读quick_check在5秒预算中断不能认定数据库损坏。本例以低优先级、256MiB/20秒CPU/45秒期限的独立进程6.694秒完成；终止、SQLite连接释放与原PID代次分别核验。不为诊断停止正常服务或扩大权限。

## 生产结果与收尾边界

当前实证：六台在线原ID的旧代次回执无剩余、当前代次保留；默认房间101条通知。原两个任务评分/操作和六个accepted完整行保持一致，旧4条unknown未改。实际管理MCP及529单工具房间票据读取通过；自有房间隧道回收、既有普通连接保留。不是普通连接冒充房间通信，也不是完整七台/业务/长期稳定性通过。

所有自有准备、测试、切换、只读诊断进程终态确定后，先保留日志回执并比对源/归档副本SHA，再逐项删除唯一暂存目录内容。只清精确自有对象，回读目录消失、当前服务和密钥引用仍有效。保留正式部署验证记录及首错；本例34项暂存764341字节清理后项目约2.798GB，无云端生产数据库备份。
