# 注册、账号等级与设备等级

## 当前入口

从获授权的后台 Origin 打开登录页；本团队使用 https://kemi-chat.newlinksz.com:21122/ 。注册和找回密码使用 hbbv 自己的数据库，不读取 HBBC 账号库。复用短信渠道不等于共享用户数据。

“验证码注册”：手机号、图片验证码、获取短信验证码、短信验证、下一步、两次密码确认，再返回正常登录。当前接受中国大陆11位手机号；密码8–1024字符，不含首尾空白。图片有效120秒/最多3次尝试，短信有效300秒/最多5次尝试；发送有60秒冷却与持久日限额。未知发送或注册提交结果先核原事务/尝试登录，不自动重复发短信或覆盖已有账号。找回密码走同样的手机号验证，成功后旧会话撤销，账号 ID 和等级保留。

真实验证码和新密码由本人按操作工具的强制要求在网页完成，不在聊天、脚本、URL、日志或 Git 中保存。不得使用生产测试验证码、直接改 users 表或绕过验证码完成所谓验收。

## 四个独立维度

| 维度 | 默认与设置 | 不能推导出的权限 |
|---|---|---|
| 后台账号 | 新注册及旧账号默认1级，范围1–10；超级管理员另设 | 10级不等于超级管理员 |
| 客户管理 | 超级管理员分配到明确 customerId | 不能借等级跨客户 |
| 房间角色 | 普通成员或管理员 | 房间管理员不自动提高账号/设备等级 |
| 设备等级 | 旧设备、新设备、邀请设备均普通（0级） | 账号提级不会自动提升已有设备 |

仅默认 admin 可由受信启动配置保持超级管理员角色；手机注册初始均为一级管理员，后续由 admin 调整1–10级。十级不等于超级管理员，旧的非 admin 超级管理员记录也不能授予该角色。注册请求不能指定 superAdmin 或等级。不要复制管理员凭据到同事设备来代替正常账号及客户权限配置。

## 超级管理员调整账号等级

1. 正常登录，核“我的账号”确实显示超级管理员。
2. 展开“用户与管理员等级”；按用户 ID 核对目标，不凭重名选人。
3. 对普通账号选择1–10级，保存后读回新等级与 revision；让该用户刷新自己的账号区域确认。
4. 超级管理员自身是独立受保护角色，列表不提供普通等级改写；不可通过提到10级制造另一个超级管理员。

现有 REST：GET `/api/v1/manage/account`；GET `/api/v1/manage/users?limit=50`（依 nextCursor 分页，单页不超过100）；PUT `/api/v1/manage/users/{userId}/level`，JSON `{"administratorLevel":2,"expectedRevision":1}`（示例1必须换成刚读取的revision）。等级必须整数1–10，不能写布尔或字符串。账号等级可由超级管理员提高或降低，409重新读取原目标，不盲重放。

API 登录使用 `X-Hbbv-Client: api`，HTTP 响应提供 accessToken；凭据仅留内存。浏览器使用 HttpOnly Cookie，写入同时核同源及 X-CSRF-Token。不要把 Store 内部的 token 字段与 HTTP API 响应或设备令牌混用。参数仍以生产 OpenAPI 为准。

## 提升设备等级

在正确客户/房间展开目标设备，核电脑昵称/原仿真 ID/安装身份与在线情况。“普通设备”与“普通成员”是两件事。展开“设备等级设置”：普通管理员只能把低等级设备提升到自己的等级；超级管理员可选择更高的1–10级。关闭编辑后恢复实时刷新；打开期间旧状态超过期限会标未知，不能把暂停刷新的旧在线当实时。

GET `/api/v1/manage/devices/{deviceId}/level` 返回 deviceLevel 与 deviceLevelRevision；PUT 同一路径，JSON `{"deviceLevel":2,"expectedRevision":0}`（示例0必须换成刚读取的deviceLevelRevision）。设备侧 GET `/api/v1/agents/me/level` 使用本设备原令牌。

该接口只提级，不支持降级。必须已有目标设备管理权、设备未撤销、安装公钥绑定核实。等级绑定安装身份；不能给未核身份或未知设备提级。同一个数值 ID 换安装密钥不继承旧高等级。普通管理员不能选比自己低的中间级或比自己更高的级别；超级管理员也不以此接口降级。并发 revision 冲突要刷新后重新决定。

## 房间内按等级仿真

先满足原同客户、已批准同房间成员、目标有效 consent、原生身份证明及工具范围。有效控制等级受设备等级和所属账号当前等级共同约束；账号降级不能让旧高等级设备继续保留更大控制权限。

同等级或低等级目标走既有房间委派，不另建逐设备白名单；访问更高等级目标返回 `ROOM_SIMULATION_HIGHER_LEVEL_APPROVAL_REQUIRED`，需设备持有人按正常白名单流程确认，不自动降低目标等级或泛放行。等级不会扩大工具目录、系统权限、证书使用或任务执行许可。新等级要核另一端实时同步、旧票据检查和真实只读调用，不能只看徽标。

## 故障和验收

- 新账号看不到客户/房间：先核客户管理分配与资源归属；账号等级不是跨客户授权。
- 找不到等级按钮：核自己是否有管理权、目标是否低于可提等级、设备是否撤销、当前是否加载最新网页。不要直写数据库补权限。
- `INSTALLATION_BINDING_REQUIRED`：恢复原安装身份的正常注册/签名证明；不复制私钥或冒充原设备。
- 409：读回原目标等级/revision；超时先查是否已完成，不重复提级。
- 短信发送失败：先核生产 provider 与私密配置。HBBC 现用 aliyun_pnvs 时不能误用普通 SendSms endpoint；两个 provider 的正式服务地址固定，不关闭 HTTPS 校验。配置由已授权部署人员处理，不读取/打印共享密钥。
