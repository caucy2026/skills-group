# 系统盘容量清理：可复用执行方法

系统盘空间不足、要求至少释放指定GB，或接续本机2026-10-13清理时读取。与容量目标规则共用授权和保护边界；此文件不授予新的删除、迁移或联系同事权限。

## 1. 固定目标和基线

先读取适用AGENTS及LOCAL-ENVIRONMENT-RULES。区分“再释放N GB”和“剩余达到N GB”：前者目标是起始可用字节加N×10^9，后者目标是N×10^9。GB与GiB不混用。记录时间、数据卷、st_dev、基线字节和目标字节。外盘清理不计入系统盘成果。

本机数据卷为`/System/Volumes/Data`；可用字节取`os.statvfs(volume).f_bavail * f_frsize`，另用`df -k`交叉核对。后续候选规范路径必须位于同一目标设备，避免经符号链接清到外盘。

## 2. 一次有界盘点，先清大项

并行检查互不重叠的根：用户Caches、Library/Developer、系统临时区、项目历史生成区；Application Support只盘点，不能整目录删。使用`du -k -d 1`，只深入大项，保存结果并复用。不要同时扫描整个HOME及其多个子目录，也不反复读取完整源码树或所有包内小文件。

本机优先核查：

1. 系统临时区中的VibeKits更新ZIP、update-extract副本。
2. `/Applications`中旧安装/回滚副本内的已核实编译二进制。
3. 项目BIN/release/candidates、历史target、Flutter和CMake编译输出。
4. 浏览器HTTP/V8、Node编译缓存、Clang模块缓存。
5. 明确被现有安装替代的旧下载、安装验证副本及IDE扩展下载缓存。

这些是发现位置，不是永久删除白名单。完整App、源码快照、依赖目录或整个build树不得按名称直接清空。

## 3. 更新保留集合和生成依据

核对当前聊天操作记录、实际安装身份/版本、构建命令、源码配置、进程参数及精确占用路径。只保护当前任务所需的精确输入，不因同产品有任务运行而永久保留所有历史输出。保留SDK/NDK/Flutter/JDK/rustup、原始依赖、源码/Git/文档、签名材料、聊天数据库、当前正式包及实际联调/恢复输入。

| 候选 | 必需核验 |
| --- | --- |
| 旧App里的二进制 | Info.plist实际身份/版本，被当前版本替代，生成来源/保留输入，Mach-O或ELF签名；包内源码样式文件和文档保留 |
| 应用ZIP/APK | ZIP内Info或aapt2实际包名/版本、旧候选/下载用途、当前交付和恢复依赖；源码/SDK归档不删 |
| DMG安装缓存 | 只读挂载，核对实际应用身份与版本被当前安装替代；卸载本次挂载后再执行删除 |
| Rust/CMake/Java对象 | 锚定实际编译目录和保留源码/构建依据；.class验证CAFEBABE及major45–70，不能误认Mach-O fat；原生输入和JNI staging不因.so扩展名变成可删 |
| Dart/Flutter | .dill等核验Dart格式；snapshot_assembly.S完整核实VM与isolate快照符号；保留原生资产、冻结依赖元数据及stamp一致性 |
| R8 mapping.txt | 核验R8生成头及历史符号丢弃授权；普通txt/文档不删 |
| HTTP/Node/V8缓存 | 确认具体生成缓存子目录；Cookies、Local Storage、sessions、queue、workspaceStorage、用户数据不纳入 |
| IDE下载缓存 | 核对对应已安装版本，保留已安装扩展原件及编译工具插件；不能顺带清扩展源码树 |

时限按最新人工授权记录。超过两天默认逐文件mtime超过48小时；后来有效的“闲置旧输出/只保留最新”等范围可取代旧时限，但须重新冻结当前保留集合，不能删除运行或发布输入。自动清理仍使用自己的时限。

## 4. 新清单、复核、顺序执行

每个候选记录规范路径、分类、生成依据、保留源码/原件、为何已不用、适用时限、device/inode/大小/mtimeNs、分配占用。扫描和删除分成独立调用，避免准备命令里的字面路径被ps误认占用。

先匹配真实进程参数，再按约100–150个精确文件做有时限lsof，避免对完整node_modules或源码快照执行巨大递归lsof。超时/报错是未知，跳过并记原因。执行前复核规范路径、设备、inode、大小、mtime与保留集合；消失、变化、占用对象跳过。不能停止同事任务来制造“未占用”。

同一卷的删除批次顺序执行。结果记录明确的`deleted/missing/changed/open/process-reference/check-timeout/protected/error`，不要仅把原候选说明复制成跳过原因。大批小文件使用增量回执或适度检查点，避免每删一个文件就重写完整巨型JSON。接续前先对账实际回执，再复核未完成对象；禁止重复运行未知结果的整批删除。

## 5. 回读和停止

每批读取实际可用字节，达到目标停止新增删除。报告分别列逻辑大小、分配占用和可用字节净变化；APFS共享块、打开的已删文件及并发读写使它们不同。不能把观测净增全归因于自己的独占删除，也不能把其他人的清理计入自己的文件数。

对再出现的路径比较原inode/大小/纳秒mtime：新生成对象保留，不重复清理；原对象仍在则不能声称删除成功。若验收前并发写入使目标再次不足，只重新核验尚未处理的旧候选，不删除刚重建的缓存。一次容量验收不保证后续构建永久维持该空闲容量。

裁剪过的历史build/App输出标为不完整、使用前需重建；明确已放弃的旧签名字节/安装包不保证恢复。不得把旧App剩余的源码/配置/文档当作可以补删的“残留”。

SDK不能删除时，同字节APFS共享块仅作为已验证的可选方法：完整SHA256相同，同设备、无占用，保留路径、权限、owner、纳秒时间及全部xattrs，未知ACL等跳过。不能以文件大小相同替代字节核验，不能把共享块数当作独占释放量。
