# 按容量目标逐目录清理：复用流程与300 GB案例

适用于用户明确要求直接清理已核实的生成物、直到指定容量达标的手动操作。此文是方法和案例，不是静态删除白名单；每次更新目录、任务依赖、授权范围和清单。

## 1. 先固定目标与范围

记录目标卷、精确目标字节、GB/GiB、时间窗口和工作区预算。复用有效授权，不重复口头确认。分别记清：历史生成物无年龄限制、当前中间缓存重置、历史回滚包/符号丢弃是否在授权内；删除源码、Git、文档、工具链、证书和密钥不属于本方法。用户要求直接执行时无需等负责人回复；技能不授予发消息权限。自动清理的时间窗口和通知规则不因本案例改变。

## 2. 一级盘点，逐个大目录深入

用 df -k / statvfs 记录可用字节，用有时限的 du -k -d 1 找最大项，再仅深入必要子树。复用有界结果，不反复扫全盘；超时是未知，不是零。按工作区归并路径，共享输入单列、父子目录不重复计数。

高收益候选包括编译对象/模块、Cargo输出、Gradle转换缓存、Office对象/PCH、Flutter中间输出；应用副本和归档常分散于 Release 产品、signed/stapled、候选/解包/rollback、历史 bin 与新构建目录继承的旧ZIP。只检查已授权根；发现同名目录嵌套递归时先核实真实内容，不盲目扩大删除。

## 3. 核验内容和保留输入

- 保留原始源码、Git和未提交状态、配置/锁文件、SDK/JDK/编译工具、平台头文件及预编译依赖输入、数据库/TLS、文档证据和当前正式签名/公证/发布字节。
- 扩展名和目录名是线索。node_modules 中的 build 可能是运行代码；.a/.so 可能是第三方输入，不能统一删除。Flutter snapshot_assembly.S 必须位于核实生成路径，并确认 Dart VM/isolate 快照符号，不能扩大到手写汇编。
- Gradle只筛核实的 transforms/.../transformed 生成物；modules-2原始依赖、wrapper分发和SDK保留。Cargo依据生成标记和依赖记录；Office依据实际 workdir 对象/PCH来源。
- .app核对根 Contents/Info.plist 的身份/版本与用途；ZIP核对主应用根、版本和归档内容，嵌套helper/LibreOffice不能冒充主应用。APK核对实际Android包名、AndroidManifest及classes.dex，不能照搬桌面Bundle ID。
- 历史包删除须有同用途保留副本，或用户明确放弃旧回滚；现有源码只能证明可重建替代产品时，不宣称能复现历史版本/原签名字节。dSYM核实DWARF用途，丢弃后旧崩溃匹配能力不再保证。
- 当前缓存重置须区分“生成物”和“下一步骤输入”。原生资产staging、native_assets元数据及stamp之间有依赖；不允许删生成库却留下输出有效的缓存状态。后续实际构建要核验最终包的ABI/原生库，编译退出0不能代替打包完整性。

## 4. 新清单、定向占用检查、顺序删除

每次生成新清单，记录精确路径、类别、来源/保留输入、删除理由、授权模式、逻辑/分配字节、device/inode/大小/mtime及占用检查。清单与结果保存在删除集合之外。执行前复核真实路径和身份，不跟随符号链接越界；消失、变化、打开、用途未知或检查超时的项跳过并记录。

先核对任务引用和进程命令，再对精确文件分批做有30秒时限的 lsof（本次100–150项），避免对大量完整源码快照 lsof +D。应用树还需核实当前运行/加载路径；一次无打开文件不能证明没有后续依赖。混合目录逐文件清理，只有核实为纯产物的应用树才整树删除。批次顺序执行，不停同事进程。工具硬性审批正常提交；被拒不能换工具绕过，先补实质证据或缩小范围。

## 5. 以实际可用容量验收并停止

每批后读取同一卷实际可用字节，达到目标立即停止新增删除。GB=bytes/10^9，GiB=bytes/2^30。逻辑大小、st_blocks×512及观测可用增量分别记录；APFS克隆/硬链接和并发写入清理导致三者不同，不能把各批分配大小相加称独占释放量。工作区预算与卷容量分别验收；未核验的工作区不得报全部达标。

## 两天闲置编译、临时截图与旧回滚

- 本次人工范围：超过48小时、已核实闲置的编译输出、临时安装/调试副本、临时调试截图和已获授权丢弃的历史回滚二进制。默认按逐文件mtime计算截止时间，同时核验当前实际用途与占用；旧目录日期、复制时继承的旧mtime或未发现编译器，都不能单独证明已不用。后续仍以用户当次范围为准。
- 编译目录可混有源码、SDK、原生资产staging及冻结元数据。只删确认生成的对象、模块、打包副本和符号；保留源代码、Git、配置、工具链和当前步骤输入。构建资源副本先定位保留原件，完整SHA256相等并复核双方stat后才能处理；原件不得随副本删除。
- 临时截图先确认来自设备/界面调试及临时目录，检查报告和交付引用。确认实际图片格式；模拟器测试目录可能有名为.png但内容为模拟文本的手写fixture，保留这些测试输入，不按图片名删除。保留产品素材、用户原始图片、当前任务截图、验收报告引用或明确作为交付证据的截图；不要按全盘PNG/JPG扩展名删除。无独占证据价值的老调试截帧在授权内直接删除。
- 回滚应用、安装归档、解包副本及dSYM核实身份、版本、生成/提取记录、保留源码与当前包；用户已放弃旧回滚时不为历史字节单独增设重复确认。当前正式包、在途签名/发布和实际依赖仍保护；旧签名字节及匹配崩溃的历史符号不保证恢复。
- Windows临时安装提取副本可用原始提取清单逐文件比对SHA256、大小和目录用途；旧下载包用实际归档结构、主程序、完整性和下载用途判定，不能仅凭.part/.zip后缀。源码归档和SDK原始安装输入不得当作应用验证包删除。
- 清单生成/脚本准备与删除调用分开。shell准备命令的字面路径可能出现在ps中，造成假占用；准备结束后用独立调用复核，不忽略真实进程、打开文件或检查超时。执行前复核路径、device/inode/大小/mtime；其他人已删、变化或占用的对象跳过，不计入自己的删除数。
- 被拒对象只在新增证据确实解决原拒绝理由时重新评估，例如原“同日范围”对象现已符合用户48小时时限、闭环记录及当前替代版本齐全；时间过去本身不解除未确认的发布/恢复依赖。保留未解决的canary等范围，不换工具绕过。
- 每批回读删除结果与实际可用字节，达到当次容量目标停止新增删除。容量目标未达就报告真实缺口；并发写入/清理与APFS共享块下，文件分配占用不等于独占物理释放。

### 2026-10-12 后续“只留今天最新版本”人工范围

用户本轮将人工清理改为“build缓存目录除今天最新版本，其余全部删除”，取代前面的48小时时限。先按实际应用/平台确认最新版本，并保留已安装/当前正式交付包、并行任务当前输入和实际占用路径；冻结新保留集合后，删除其余核实的生成输出，无需重复取得同范围批准。较大编译文件与小型class/object文件分别扫描，小型class校验真实CAFEBABE及版本，避免只清大文件却留下大量小型编译缓存。最终归档须核对实际交付状态，不把final或notary文件名当用途证明；已明确未发布的旧候选包、闭环旧公证临时包可按授权删除，当前或未确认交付用途的包单列。

“只留最新”不授权清除原始源码/Git/配置/SDK/签名材料，或删除未解除的恢复依赖。旧build树含这些输入时逐文件处理，不能承诺整个混合目录为空。该人工范围不改变自动任务的时限；本轮实际保留版本与文件清单只用于当次记录，下一轮重新核验。

### 按所有项目的 build 缓存减半

用户要求每项目缓存减半时，冻结每项目实际生成目录的基线，按同一组路径复测；源码、SDK、历史工作区总量与 build 缓存分别计量。父子路径去重，共享缓存单列；新增或遗漏路径另建基线，不能混入旧基线计算比例。清理期间最新构建可能增长，最终比例必须用复测值，不能仅加总删除清单。

逐项目核验来源和当前依赖后执行，不只处理两个最大项目。Flutter 自动生成的 snapshot_assembly.S 须读取完整内容核实 VM 与 isolate 快照符号，符号可能不在文件头。Rust 增量文件核实 RSIC 格式，并用对应 crate 的 depfile 定位保留源码；相对路径须结合实际源码根解析，不能假设工作区顶层就是 Cargo 项目。资源归档副本须完整 SHA256 相等、保留原件和双方 stat，编译工具链原始输入继续保留。

没有主程序的旧 App 树应标为不完整历史输出，不能当作完整回滚资产，也不能因此直接删剩余混合内容。用途未明、当前输入、归档或正式包导致无法减半时，列出该项目基线、剩余字节和精确保留原因；不可用删除输入凑比例，也不可把两大项目达标写成所有项目达标。扫描超时、未分类目录和工具阻断独立记录。

本机 2026-10-12 的逐项目基线、清单与实测结果保存于清理证据的 `cleanup-20261012/half-per-project/`。这是执行案例，后续更新版本、保留集合、占用和时间范围，不能直接复用删除名单。

### 2026-10-13 接续：查新增占用与避免反复复制

先对照上次结束的实际可用字节，找新增或重新生成的最大目录，再复用旧盘点核查其他项目。不以再次遍历所有历史源码、SDK或包内源码代替清理；未分类目录先做有时限的大小测量，大项才深入。聊天记录、实际安装版本、源目录版本和进程同时核对：本机装了更高版本，不代表远端仍运行的旧版本及其恢复入口已废弃。

SDK与预编译输入必须保留时，可以沿用已验证的APFS同字节共享块方法：完整SHA256相等，路径、权限、owner、纳秒时间、xattrs和字节均不改变；排除在用目标、符号链接、未知ACL和不可核验对象。只读原件，不修改当前工作区。`node_modules`中的源码和运行代码不得删除，但其已核实的相同SDK二进制副本可以按此方法共享存储；这不等于清除依赖输入。新临时SDK快照优先沿用同等字节/元数据保证的APFS克隆方式，避免每个版本重新写入整份输入，不因此修改当前运行任务。

### 2026-10-13 系统盘净释放50 GB

系统盘本轮目标是可用字节比起始增加50,000,000,000，不是剩余空间达到50 GB。起始4.533428 GB、核验末次54.542602 GB，观测净增50.009174 GB后停止新增删除；并发构建仍可能改变后续读数。证据见本清理聊天`cleanup-20261013-system50/summary.json`及各批精确清单和结果。删除139,106个旧生成文件、安装缓存及归档；执行核验时跳过32项，9个SDK二进制仅共享块，原始SDK与工具链不删。

优先核查系统临时目录里的更新解压副本、应用目录的历史安装二进制、旧候选包和编译对象，再检查浏览器HTTP/V8、Node编译缓存。保留原始源码、Git、文档、聊天历史/状态、当前安装和联调恢复输入。不要按App版本保护或删除整个产品的所有历史路径：本轮保留2653、2651/2652及远端2640/2638，清理低于保留范围的闲置生成对象。

目录名或时间不证明安装缓存可删：读取ZIP内Info、APK实际身份/版本；DMG只读挂载核验身份及被当前安装版本替代，再卸载本次挂载后删除。IDE扩展安装下载缓存必须核对相应已安装版本，保留扩展原件和编译工具插件。混合App树保留源码样式文件和文档，只剪已核验生成二进制。旧构建裁剪后需重建；授权放弃的历史安装/回滚字节不保证恢复。

删除回读时，某些编译缓存会被同事重新生成到原路径。用原inode、大小和纳秒mtime区分未删成功与新对象，不把新生成文件再次删除，也不能把路径再次存在写成原删除失败。本轮53条Clang/Swift缓存路径已被重新生成，原精确对象均已删除。
