# 构建资源不足与升级恢复：已验证的方法

仅用于已授权设备、已核空闲客户端和本任务构建。具体ID、路径、PID、出生时间、门槛与包哈希从当前项目台账读取。

- 分清机器可用RAM、系统commit和单个仿真命令的进程预算。PS7读取自身配置时OutOfMemory可能来自命令进程的512MB预算，不是执行策略拒绝；先保留错误。长构建沿既定独立交互任务运行，正常PS7 -File与策略不变。禁止绕过真实UnauthorizedAccess。
- 不降低既有构建门槛、不结束别人的软件。资源只差少量时，核对本任务客户端实时界面、任务状态、精确路径、签名、PID及同API出生时间。若确已空闲，可在独立恢复守护就绪后正常关闭该客户端；正常关闭超时后，仅在授权涵盖且身份fence仍匹配时结束这一实例。
- 恢复守护必须由独立交互任务持有，检查真实PID/路径/会话。构建finally恢复原已核签名程序，另有有界超时恢复；守护终态后再回收临时任务登记。旧版本恢复后读取新PID，不能沿旧PID继续签名或安装。
- 桌面与仿真配合观察同一事务。窗口不存在时用登记远程办公ID打开新连接窗口并核标题，不停止办公服务。文本发送成功不代表真实远端字符串正确；确认焦点与完整目标文本后才执行。借剪贴板同步时原数据只在内存保存并恢复，不输出或保存用户剪贴板。
- SCP超时保留部分文件，先核原传输已终止、目标大小与剩余空间。原可信SFTP可用时续传同一文件，完成后校验完整大小/SHA再解包验签；不重复整包覆盖未知事务。
- Mac升级使用已验证独立launchd守护、AbandonProcessGroup和原安装路径。比较主程序及助手BID/Team/DR/权限后再替换，保留旧包。原ID重连、实际只读工具、安装版本/哈希、原安装身份和实时房间均通过后提交健康ACK；守护退出、卸载登记后再次确认App存活。首次初始化remote_disabled不当作正常通过，继续恢复并复验。
- 无相关源码或输入变化的已通过证明可以复用；必须先核实际源文件/输入哈希相同，并在新回执写清旧证明来源与复用范围。不要改旧报告日期、PID或版本，不把复用说成新版本重新跑过。签名与包字节变化后的检查及覆盖后授权实测仍不可省略。

实证索引：项目ROOM_UI_SIGNING_CONTINUATION_20261013.md；四台Mac664覆盖、Windows664完整Release475.684秒和独立恢复、244PE暂存及9项凭据源码一致性。只证明对应阶段，七台Windows覆盖、长期稳定和完整G01–G10按台账继续。

- Windows 存活判断先调用 GetExitCodeProcess 并要求 STILL_ACTIVE（259），再读取创建时间核身份。已退出但进程对象仍被持有时，GetProcessTimes 仍可成功；不能据创建时间误判活着、重复升级或触发错误回退。2026-10-15 Windows58的前两次正常退出被错误判超时，v4补真实退出码后正常关闭并覆盖664、原ID实调及健康ACK、守护terminal0后存活通过；不要把该控制端误判当成产品不能退出。
- 安装器健康ACK有既定期限。新主进程启动后优先完成原ID/FP、真实MCP、实际版本与签名、小文件传输和实时默认房间核验，再写同一attempt/PID/出生时间绑定的ACK；不要先整理报告而错过期限。619首次因迟到未ACK真实回退，第二次即时核验后terminal0；保留失败，不重写历史。

- 桌面反射画面不是离线证据：2026-10-15 Windows617先前显示控制Mac的递归画面，缓存窗口/CLI打开也未证明新握手。回到已授权办公主界面，核对完整目标ID后点击真实“连接”，取得Windows本机桌面与原办公ID，再启动原564桌面快捷方式。不要在反射画面按坐标操作；恢复后仍核原仿真ID/FP、原事务与实时房间。

## 心跳超限与共享主机I/O争用

- 区分设备离线、服务阻塞和采样窗口失败。保留同一PID/创建时间、真实心跳年龄、HTTPS超时类别、线程等待、主机PSI及进程I/O短时差分；CPU低或磁盘剩余充足不能排除读盘争用。只看累计I/O不能判断当前负载。
- 只采集诊断所需的进程名、ID、创建时间及读写差分；确认归属时读取必要工作目录/可执行路径，不打印命令参数、环境、凭据或其他项目业务内容。发现其他项目在途工作，不终止、改优先级、删缓存或擅自发消息；先核本服务是否仍正常、是否需要代码回退。
- 现场资源条件实测变化后，用相同设备、在线阈值、采样间隔及持续时间复测。保留失败窗口，不通过增加在线阈值、只挑恢复样本、重启或写报告把失败改成成功。相关性不能直接认定唯一根因。
- 2026-10-22同一hbbv进程在高I/O窗口有12个心跳超限点及2次HTTPS超时；磁盘压力下降后，同参数120秒/9次中六台均9/9正常、HTTPS9/9、最大心跳不足4秒，617仍预期离线。仅证明该短窗口恢复，不代表24/72小时、统一升级或全功能通过。完整索引见项目`docs/acceptance/FLEET_STABILITY_RECOVERY_AND_WINDOWS619_20261022.md`。
- 观测结束核原PID/创建时间及terminal，再保存脱敏汇总、原始SHA和必要失败证据；按cloud-build-cleanup清理自有脚本/采样/空日志并读回，不把清理几KB说成解决整机I/O争用。先核既有观察器已结束才启动新一轮，避免重复采样增加负担。


## 大安装包超时后的受控LAN续传

适用于已有同机暂存授权、公开分发安装包或已明确批准向该设备传送的签名候选包；不用于私密工作区、数据库、密钥或用户文件，也不代表可以安装未验收候选。

- 工具审批/安全策略拒绝不走此替代路线。普通资源超时先对账原SCP的精确PID/创建时间与终态、接收文件大小、是否仍被打开，未知结果不并发写同一文件。保留首败；先复用已登记且可达的可信SFTP等既有备用入口。
- 需要同LAN取文件时，用原已验证仿真SSH读目标实际IPv4/掩码，与名称解析及当前设备身份对账；不从设备昵称或ID推测IP。只绑定控制端实际私网IPv4，只允许该目标IP，只提供一个已核大小/SHA的包，不启动整个工作目录的HTTP目录服务器，不改防火墙、代理策略或云端端口，不创建云端临时包以绕过存储上限。
- 可复用[单安装包有限时段提供器](../scripts/serve_one_release_archive.py)：先有签名/公证及授权证明，再准备独立目录的intent JSON（localTransferFile绝对路径、sha256、bytes）。在macOS/Linux独立进程用python3 -B脚本配合--intent、--bind、--peer、--state执行；Windows控制端不使用此POSIX限时入口。脚本拒绝通配/公网IPv4，核源SHA、仅固定包路径、目标IP、ETag及Range，64KiB流式发送，15分钟总时限。它不替调用者验证签名或授予发布权限，状态文件不是签名证明。
- 先用小Range到/dev/null验证206与可达性；原写入者确认终止且本次独占部分文件关闭后，用有界curl --continue-at -、If-Match、禁止重试/重定向对同一包续传。数据仅为已获准的包，完整大小及SHA必须通过原可信通道独立核验，再做任何安装；HTTP探测或下载退出0本身不够。接收文件不执行，不混用旧包前缀。
- 完成后按PID/创建时间停止自有提供器，确认进程退出、端口不监听并保存必要收据。临时硬链接只在另一个正式完整包仍存在且同inode时移除；逻辑443MB不等于释放443MB物理空间。目标暂存只在后续升级/回退有明确用途时保留，过时后按精确SHA清理。

2026-10-22真实索引：VibeKits项目docs/acceptance/MAC132_754_PREFLIGHT_STAGED_20261022.md。旧SCP资源期限结束、原进程退出后，从295,587,840字节断点续传148,089,028字节，用时10.985秒；完整443,676,868字节/SHA通过、723未退出。只证明暂存，不是升级/长期性能或所有网络环境均可用。


## Mac跑分组件的系统基线与解释器

- 客户Mac可能没有CLT；系统python3可能只是触发安装的stub。只读诊断先用已有MCP能力、系统现成命令或已核身份的App自带Node；不为读取元数据安装开发工具。遇到安装按需进程先核启动时间/归属，不能把既有安装器当本轮新进程终止。
- 看实际Mach-O LC_BUILD_VERSION与架构，不把空CMake部署字段当低版本兼容证明。已构建组件满足真实目标系统时复用原SHA；新签名须重新记录SHA、公证及接收端校验，保留许可证/对应源码/构建信息，不向已签名App里直接复制组件。
- 固定clpeak3.0.0的Metal实现仅接受Apple silicon；Intel GPU枚举可见也可能被它跳过。此限制属于该引擎实现，不是“Metal API不支持Intel”。Intel设备改用已核系统OpenCL路径时，仍需固定版本、API、构建输入、签名及真实GPU输出；CPU回退、枚举与退出0不能冒充GPU通过。
- 原资源判定显式notStarted、没有执行意图和子进程时，资源实测变化后才另记重试；在途或未知结果不能重发。硬件成绩和严格空闲门禁分开；后台任务不能为跑分被强停。项目实证见VibeKits docs/acceptance/MAC132_BENCHMARK_COMPONENT_20261023.md与MAC_ARM_BENCHMARK_COMPONENT_20261023.md，不能据此宣称8台或App内入口全部完成。
