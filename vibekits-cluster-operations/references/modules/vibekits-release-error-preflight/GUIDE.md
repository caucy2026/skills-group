# VibeKits 发布历史错误强制验收

快照出现文件数或字节预算失败时，补读 [PAD 快照容量与覆盖前保护](../vibekits-pad-development/references/snapshot-capacity-migration.md)：联合核对生产、存储、恢复及读回上限，保护新增数据；非敏感 fixture 或旧 generation 通过不能替代最终真实保护。本补充不改变固定77项。

用户明确要求每次发布前执行本技能。它是已有发布流程的事故补充门禁，不替代构建、签名、真机验收或商城发布技能。

发布依赖宿主的 PAD Builder 组件时，另读 [Builder 组件适用检查](references/pad-builder-component-release.md)。项目检查器按真实 APK 包名、签名及已验证不可变产物选择组件分支；主 APK 的固定77项原分支保持不变，禁止给主 APK 改标签规避。组件预发布通过仍不等于商城交付通过。

## 每次必须执行

1. 先完整读取本技能与 [错误台账](references/errors.md)；PAD还必须逐项执行 [身份与启动验收表](references/pad-identity-startup-20261009.md)。在当前项目读取 `docs/acceptance/BUILD_RELEASE_INCIDENTS_2026-10-03.md`、本次新增事故记录及适用本机环境规则。沿用最近成功的实际命令，记录 argv、cwd、环境引用和精确输入哈希；不扫描或打印密钥。
2. 为每个适用的错误族建立本版回归结果。使用 `app-release-stability-gate` 的既有执行器和真实设备；明确原触发、实际动作、禁止结果与证据。未测、失败、结果未知均 BLOCK，不能以版本、PID、灯、菜单、签名、编译或上传成功代替。
3. 新增修复必须证明旧实现/故障注入会失败、修后通过。网络、并发、生命周期回归至少三次；保留首次失败。最终签名包覆盖已授权旧版，不清数据，实测原 ID、授权、Key、名单、会话和工具。
4. 在精确正式包上运行项目 `tool/check_release_error_preflight.py <receipt.json>`。发布前 phase=prepublish；交付收尾 phase=delivery，后者额外要求交付/清理结果，不能要求未发布时伪造收尾成功。回执需绑定包路径/字节/SHA、平台、版本、构建号与所有适用 case 的实测证据文件。脚本只检查证据完整性及字节身份，**不替代功能测试**。缺项、非 PASS、证据丢失/变动或正式包变动即拒绝。
5. 只有上述检查及原发布门禁都 PASS，才沿已有获授权渠道发布同一 SHA；回读商城元数据、下载字节和用户安装/更新行为。完成云端源码/改动记录备份后读回验证，不上传凭据、聊天或私有救援包。用过云端编译必须执行 `cloud-build-cleanup`；清理仅本任务已退出且可再生的产物，保留当前正式包、源码、签名材料和证据。

## 本次特别拦截

- macOS 冻结构建必须执行错误台账的 `version-identity` 检查：构建前核对 pubspec、Dart 常量及两份生成配置，构建后增加实际 APP 路径核对。共享签名脚本的隔离构建须将 `VIBEKITS_BUILD_SOURCE_ROOT` 指向真实构建源码；不得只修改 Xcode 参数或 Info.plist。覆盖后核实时桥版本及实际监听 PID，公证 Accepted 不能替代运行版本一致性。详见 [616 事故补充](references/errors.md#mac616-冻结版本遗漏2026-10-11)。

- PAD安装探针/组件也必须遵循非增量文件安装路线；63已实测DataLoader/eventfd内核panic。先传APK并校验，再pm install；禁止裸adb install及忽略增量失败后的回退Success，详见错误台账。

- Android 的 APK 是安装包，不是桌面可执行文件。仿真离线或再次进入时不得执行 APK、桌面 stop/takeover；通过本机服务/JNI 恢复，保留真实注册状态。实机出现 `HARNESS_RELAY_NOT_CALLABLE` + `ProcessException` + `Permission denied` 必须定位和修复。
- “正在开启”必须代表实际开启事务。连接恢复/注册失败不能无限显示忙碌；显示真实错误及可恢复状态，不能只改绿灯或放宽注册条件。
- 卸载主程序再装的 Key 恢复范围必须真实验收。用户保存新 Key 后，正式 SDK 和持久保险库均以新值为准；旧备份不得覆盖。全组件卸载未经验证不得宣称已支持。
- 数字 ID 不变不足以证明身份不变。2026-10-09 服务端实际记录 207 的 UUID_MISMATCH；原私有救援身份公钥指纹与服务端旧身份匹配。覆盖升级必须保留完整原认证身份；卸载重装按下方最新规则重新认证。检查真实注册响应，不能忽略UUID校验冒充成功。
- 仿真断联先核对控制桥、原事务及登记的同机备用通道。备用通道首先读状态和回执，不因断联重复安装、启动或删除。已确认离线的远程桌面按用户要求不连接。

遇到新事故，先给错误台账新增独立 ID、触发与永久回归，再修复；不能用新增文档、反复轮询或准备完成代替执行。遵守有效授权及系统审批，技能不能授权绕过拒绝。

## 启动可用性第一硬门禁（2026-10-09最新用户规则）

主程序必须进入可操作界面；Key输入、设置和必要认证入口不得依赖远程注册成功。最终签名包必须验证：缺失/失效Key、服务器离线、同ID新认证密钥被拒、硬件ID变化、注册失败及调用不返回。失败有截止时间、结束忙状态、明确原因及人工恢复入口；迟到结果不得覆盖新事务，后台不得无限重试。主界面能操作不代表服务器在线或仿真成功。

覆盖升级保留认证身份。PAD卸载主APK删除传输认证密钥及helper身份副本，重新安装走新设备认证；硬件ID不变保留配置/API Key/会话，硬件ID变化只清旧设备绑定配置与凭据，进入可操作初始界面。不得把同ID换密钥误判为ID变化，不得仅凭MAC覆盖服务端旧身份。此规则取代此前普通卸载也要求保留认证密钥的条款。

新增startup-recoverability必验项：保存原触发、最大等待界限、实际Key输入/设置动作、配置保留或清理断言；冷启动、再次进入、覆盖升级、卸载重装分别验收。网络/并发/生命周期至少三次，硬件ID变化用隔离fixture或获授权实机，不改真实MAC。无限等待、无法输入Key、启动崩溃均BLOCK。

启动可用性实机还须覆盖底层服务生命周期：STATUS/高级页轮询必须只读，不能隐式绑定并启动服务；注册截止后的至少三次轮询及页面重入不得复活relay或重置截止。明确人工重试才恢复认证事务。分别记录外层UI重试与实际native服务PID/启动次数，不能仅凭Dart fixture通过推定底层循环已停止。2026-10-09的585实测未通过此项，必须保留失败证据。

2026-10-09最新要求：正常启动直接进入应用，不弹前置检查/恢复页；后台检查不得阻塞Key入口或覆盖活跃文件。ID算法版本、当前计算ID、当前身份scope与最后真实注册成功记录分开保存；明确变化执行一次有持久阶段的迁移，pending/失败重启不得反复删除新身份。旧版本无记录标unknown；断网/超时不能伪称服务器明确拒绝。同ID密钥冲突与算法/ID变化分别验收，停止循环不等于重新注册成功。

Android手动开启必须使用生产默认指纹读取路径验收，禁止用mock relayFingerprint掩盖URI/路径错误。idle/paused/failed/live四种状态都必须保留当前已安装APK信息；android://逻辑标识不能File.openRead，更不能要求PAD拥有桌面vibekits-harness-relay程序。覆盖安装后验证实际新进程及包路径，再做暂停后手动重试；PackageManager版本/包hash不单独证明运行进程已更新。

## PAD 整周历史异常永久门禁（2026-10-10）

每次PAD构建、覆盖升级及发布前必须完整读取 [整周事故与永久验收基线](references/pad-weekly-incidents-20261010.md)，逐项处理项目 `tool/pad_release_incident_matrix.json` 中全部固定case。本次基线为最近七天的63项异常/风险与13项功能验收；这是长期历史回归，不得下周滚动删除，也不得把故障类别数说成实际发生次数。

修复状态与最终包验收分开。旧包、隔离fixture、编译/签名或上传成功不得替代最终包真实行为；未上线候选缺陷、用户报告未证根因、设施误差保留各自边界。最终包必须完成新机注册、首次白名单及真实仿真调用，不能因旧设备已有授权通过而关闭新机门禁；注册失败需读当前PID和初始化阶段，拒绝旧缓存充当实时证据。

发布检查器PAD回执必须包含 `padIncidentMatrixSha256`，绑定当前固定矩阵字节；`prepublish` 与 `delivery` 两阶段均检查每项PASS、同一最终artifact SHA及非空证据内容SHA。缺矩阵、缺项、未测、失败、证据未知或变动、旧包证据均阻断。新增矩阵项后旧回执自动失效；严禁为了通过而伪造PASS、删case或挪成可选项。桌面既有门禁保持原范围。只通过构建的候选可用于已授权诊断，不得标为整周异常全部修复或发布正式更新。
